# 新手部署与使用指南

这份文档面向第一次使用 Docker、New API 和 epusdt 的用户。按顺序操作即可，不要跳步。

项目实现的是：邮箱注册 → USDT/USDC 充值 → 创建 API 令牌 → 调用 OpenAI 兼容接口或 Seedance → 按量扣额度。

明确不包含：KYC、法币、提现、退款、分销、白标，也不包含“连接 MetaMask/TronLink”的钱包签名登录。

## 一、先认识四个网址和两套管理员密码

本地默认网址：

| 用途 | 地址 |
| --- | --- |
| 普通用户网站 | `https://localhost` |
| 用户收银台 | `https://pay.localhost` |
| New API 管理后台 | `https://newapi.localhost` |
| epusdt 收款后台 | `https://epusdt.localhost` |

有两个不同的管理系统，不要把它们的密码混在一起：

1. **网站外层 Basic Auth**：保护两个管理后台的页面，由项目 `.env` 中的 `ADMIN_BASIC_AUTH_HASH` 决定。
2. **系统自己的管理员账号**：
   - New API 使用首次初始化时创建的管理员账号；
   - epusdt 使用首启生成的 `admin` 账号，首次登录后应修改密码。

普通注册用户没有“渠道”等管理菜单，这是正常现象。

## 二、安装 Windows 运行环境

### 1. 安装 Docker Desktop

官方文档：<https://docs.docker.com/desktop/setup/install/windows-install/>

下载 Windows x86_64 安装包并安装。Docker 依赖 WSL 2；如果安装器提示 `Virtual Machine Platform` 未启用，需要管理员权限。

### 2. 如果 WSL 安装出现 403

`wsl --install` 的在线下载可能被网络拦截。可以尝试在**管理员 PowerShell**中执行：

```powershell
wsl --install --web-download
```

也可以从微软官方仓库下载 WSL MSI：

<https://github.com/microsoft/WSL/releases/latest>

安装 MSI 后，在**管理员 PowerShell**执行：

```powershell
dism.exe /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
```

然后重启电脑，启动 Docker Desktop，等待 Engine 正常。

### 3. 网络代理（按需）

如果你使用本机 VPN 代理，例如端口 `7897`：

1. 打开 Docker Desktop。
2. 进入 **Settings → Resources → Proxies**。
3. 开启手动代理。
4. HTTP/HTTPS 代理填写 `http://127.0.0.1:7897`。
5. 点击 **Apply & Restart**。

如果 `docker pull` 能用、构建却仍无法访问 `auth.docker.io`，可先手动预拉取镜像，再重新构建。例如：

```powershell
docker pull alpine:3.22.2
docker pull python:3.12-slim
```

New API/epusdt 的其他固定基础镜像见各自的 Dockerfile。

## 三、准备项目配置

在项目根目录打开 PowerShell：

```powershell
cd D:\daily_update\crypto-llm-mvp
Copy-Item .env.example .env
```

如果已经存在 `.env`，不要再次覆盖。用记事本打开：

```powershell
notepad .env
```

### 1. 填写核心随机密钥

至少替换这些 `CHANGE_ME`：

```dotenv
POSTGRES_PASSWORD=随机长字符串
REDIS_PASSWORD=随机长字符串
SESSION_SECRET=随机长字符串
EPAY_HMAC_KEY=随机长字符串
EPAY_MD5_KEY=随机长字符串
```

可以用 Python 逐个生成：

```powershell
python -c "import secrets; print(secrets.token_hex(32))"
```

注意：

- 不要把真实 `.env` 上传到 GitHub或发给他人。
- `POSTGRES_PASSWORD` 建议只用字母和数字，避免 URL/Compose 特殊字符。
- 同步修改 `ADAPTER_PG_DSN` 中的密码，使其与 `POSTGRES_PASSWORD` 一致。

### 2. 设置管理页面 Basic Auth

先想一个外层管理密码，然后生成 bcrypt 哈希：

```powershell
docker run --rm caddy:2-alpine caddy hash-password --plaintext '替换为你的外层管理密码'
```

把输出填入 `.env`，整个哈希必须用单引号包裹：

```dotenv
ADMIN_BASIC_AUTH_HASH='$2a$...'
```

Basic Auth 用户名默认是 `admin`。外层密码由你自己保存，不要把明文密码提交到仓库。

### 3. 本地域名

保留默认值：

```dotenv
SITE_DOMAIN=localhost
PAY_DOMAIN=pay.localhost
NEW_API_ADMIN_DOMAIN=newapi.localhost
EPUSDT_ADMIN_DOMAIN=epusdt.localhost
NEW_API_BASE_URL=https://newapi.localhost
EPUSDT_BASE_URL=https://epusdt.localhost
ACME_EMAIL=
```

本地空 `ACME_EMAIL` 会自动使用内部测试值，不影响 localhost 证书。

在**管理员 PowerShell**中添加一次本地解析：

```powershell
Add-Content -Path "$env:SystemRoot\System32\drivers\etc\hosts" -Value "127.0.0.1 newapi.localhost epusdt.localhost pay.localhost"
ipconfig /flushdns
```

### 4. 让 Python 脚本信任本地 Caddy 证书

服务首次启动后，在项目根目录执行：

```powershell
New-Item -ItemType Directory -Force .cache | Out-Null
docker compose exec -T gateway sh -c "cat /data/caddy/pki/authorities/local/root.crt" | Set-Content -Encoding ascii .cache/caddy-local-root.crt
$env:SSL_CERT_FILE="$PWD\.cache\caddy-local-root.crt"
```

`SSL_CERT_FILE` 只对当前 PowerShell 窗口有效。以后新开窗口运行脚本时需要重新设置。

## 四、第一次启动底座

PowerShell：

```powershell
.\start.ps1 -Base
```

如果 PowerShell 禁止执行脚本，可使用：

```powershell
powershell -ExecutionPolicy Bypass -File .\start.ps1 -Base
```

Git Bash 则可执行：

```bash
./start.sh --base
```

启动以下服务：PostgreSQL、Redis、New API、epusdt、Caddy gateway。

检查状态：

```powershell
docker compose ps
```

如果脚本失败，先看最上方的错误；不要只看最后的提示。当前脚本会在构建失败时返回非零退出码。

## 五、初始化 New API

1. 打开 <https://newapi.localhost>。
2. 通过外层 Basic Auth。
3. 按页面向导创建第一个 New API 管理员。
4. 这个账号自动是 root，用户名不必叫 `root`。
5. 把该账号密码回填 `.env`：

```dotenv
NEW_API_ADMIN_USERNAME=你的初始化账号
NEW_API_ADMIN_PASSWORD=你的初始化密码
```

不要使用公开注册页面创建的普通用户账号。

## 六、配置 epusdt 收款

### 1. 登录 epusdt

打开 <https://epusdt.localhost>。

先通过外层 Basic Auth，再登录 epusdt。首启管理员密码可查看：

```powershell
docker compose logs epusdt
```

搜索 `Default admin account created`。登录后立即修改初始密码，并把新密码回填：

```dotenv
EPUSDT_ADMIN_USERNAME=admin
EPUSDT_ADMIN_PASSWORD=修改后的epusdt密码
```

### 2. 添加收款地址

进入左侧 **地址管理 → 添加地址**，分别添加：

| 网络 | 代币 | 地址格式 |
| --- | --- | --- |
| TRON / tron | USDT | 你的 TRON 地址，通常以 `T` 开头 |
| Ethereum / ethereum | USDC | 你的 Ethereum 地址，`0x` 开头 |
| Polygon / polygon | USDC | 你的 Polygon 地址，`0x` 开头 |

只填公开地址，**绝不填写私钥或助记词**。同一个 EVM 地址可以同时用于 Ethereum 和 Polygon，但要分别建立记录。

当前 adapter 和对账只开放上述三种组合，不要仅凭后台已有选项就启用其他链。

### 3. 配置链、代币和 RPC

1. 在 **链与代币**中只启用 USDT/TRON、USDC/Ethereum、USDC/Polygon。
2. Polygon 使用原生 USDC 合约：`0x3c499c542cEF5E3811e1192ce70d8cC03d5c3359`，不要误用 USDC.e。
3. 在 **RPC 节点**添加稳定节点：
   - TRON：TronGrid API Key；
   - Ethereum/Polygon：稳定的 WSS RPC。
4. 执行节点健康检查，确认对应链可用。

### 4. 配置确认时外部汇率

在系统设置中：

```text
rate.mode=auto
rate.api_url=可靠的外部汇率源
rate.cache_ttl_seconds=300
```

手动刷新并确认 CNY 快照同时包含 `usd`、`usdt`、`usdc`，状态新鲜且成功。

系统按链上实收数量和确认时汇率入账，不使用 1:1 面值 fallback。页面的 `1 USD = 1 USDT` 只是稳定币标价显示约定。

### 5. 创建 GMPay API Key

进入 **支付管理 / API Keys**，创建 GMPay 密钥，IP 白名单填写 adapter 容器地址：

```text
172.30.250.30
```

把生成的商户号和密钥回填 `.env`：

```dotenv
GMPAY_PID=你的商户PID
GMPAY_SECRET_KEY=你的GMPay密钥
```

epusdt 与 adapter 使用 GMPay v2 HMAC-SHA256；不要选择旧 MD5 回调。

## 七、初始化支付、定价和供应商渠道

在 `.env` 中继续填写真实 SMTP 和上游密钥，避免把 `CHANGE_ME` 写入 New API：

```dotenv
SMTP_HOST=真实SMTP服务器
SMTP_USERNAME=真实账号
SMTP_PASSWORD=真实密码
SMTP_FROM=真实发件地址
OPENAI_CHANNEL_1_KEY=真实上游Key
ARK_API_KEY=真实火山方舟Key
```

然后执行：

```powershell
python scripts/bootstrap.py --check
python scripts/bootstrap.py --apply
python scripts/validate_pricing.py
```

作用包括：开启邮箱验证码、设置 USDT 展示、配置三种 Crypto 支付方式、创建 OpenAI/Doubao 渠道、导入定价。

`--check` 只是检查并列出待变更项；`--apply` 才实际写入。

## 八、启动支付与对账服务

只启动支付适配器：

```powershell
docker compose up -d --build payment-adapter
docker compose ps payment-adapter
```

健康状态应为 `healthy`。

配置好 TronGrid、Etherscan、Telegram 和三个钱包地址后，可启动每日对账：

```powershell
docker compose up -d --build reconciler
```

完整启动：

```powershell
.\start.ps1
```

## 九、普通用户怎么充值

1. 打开 <https://localhost>。
2. 注册邮箱账号并登录。
3. 进入 **钱包 / Wallet**。
4. 输入充值金额。
5. 选择 `USDT-TRC20`、`USDC-ERC20` 或 `USDC-Polygon`。
6. 页面跳转到 `pay.localhost` 收银台。
7. 用自己的钱包向收银台显示的地址转账。
8. 等链上确认后，系统自动验签、核对交易并增加额度。

不需要连接钱包，不需要在网站上输入私钥。重复回调不会重复入账。

## 十、配置供应商 API 池

使用 New API root 登录 <https://newapi.localhost>，进入 **渠道 → 添加渠道**。

同一个 OpenAI 兼容供应商有多个 Key 时：

1. 类型选择 OpenAI。
2. Base URL 填供应商地址，末尾不要加 `/v1`。
3. Add Mode 选择 **Multi-Key Mode (multiple keys, one channel)**。
4. 每行填写一个 Key。
5. 策略选择 Polling 或 Random；本项目已有 Redis。
6. Groups 勾选 `default`。
7. 填写模型并保存、测试。

不同供应商或不同 Base URL 应建立不同渠道，再用优先级和权重控制负载。

Seedance 使用单独的 Doubao/火山方舟渠道，不要放进 OpenAI 渠道。

## 十一、调整定价

定价文件是 `pricing/model_ratios.json`：

- 文本：`model_ratio` + `completion_ratio`，按 token；
- Seedance/Seedream：`model_price`，默认按次；
- 页面以 USDT 标价，USDC 可作为等价付款方式。

修改后执行：

```powershell
python scripts/validate_pricing.py
python scripts/bootstrap.py --apply
```

默认非零数值只是初始运营值，营业前必须按真实成本、视频时长/分辨率和利润率核对。单位细节见 `pricing/README.md`。

## 十二、验收、对账和备份

### 真实验收

```powershell
pip install -r scripts/requirements.txt
python scripts/acceptance.py --all --payment-timeout 900 --restart
```

验收需要真实邮箱、真实上游 Key 和真实链上小额付款。缺条件会显示 BLOCKED，不会伪造 PASS。

### 手动对账

```powershell
python scripts/reconcile.py
```

对账检查 epusdt、adapter/New API 和链上实际到账，包括邮箱、收付款地址、tx hash、代币合约、确认时汇率和额度。差异写报告并发送 Telegram 通知。

### 常用命令

```powershell
docker compose ps
docker compose logs -f new-api
docker compose logs -f epusdt
docker compose logs -f payment-adapter
docker compose restart
```

不要删除命名卷。备份至少包含 PostgreSQL、epusdt `/data`、New API `/data`、Redis 和对账报告。

## 十三、常见报错对照

| 现象 | 原因与处理 |
| --- | --- |
| 没有“渠道”菜单 | 当前是普通用户；改用 New API 初始化时创建的 root 账号。 |
| 用户端没有可用充值 | 支付初始化或 adapter 未完成；先完成第六至八节。 |
| 管理后台反复出现浏览器登录弹窗 | 分清外层 Basic Auth 和系统管理员密码；使用当前网关版本，公共 API 不应再被 Basic Auth 误拦截。 |
| `SSL: UNEXPECTED_EOF_WHILE_READING` | 检查 hosts，并设置 `SSL_CERT_FILE` 指向本地 Caddy 根证书。 |
| `auth.docker.io` 连接失败 | 配置 Docker Desktop 代理并重启；必要时先 `docker pull` 预拉取基础镜像。 |
| `payment gateway unavailable` | 看 `docker compose logs payment-adapter` 和 epusdt 日志；检查 GMPay 密钥、钱包、RPC、汇率。 |
| `invalid notify url` | 使用当前 epusdt 补丁和 Compose 配置；不要删除 `EPUSDT_INTERNAL_NOTIFY_URL`。 |
| `No module named psycopg2` | 使用当前 Compose；SQLAlchemy DSN 应为 `postgresql+psycopg://`。 |
| epusdt 没有管理员 | 使用当前 PostgreSQL 兼容补丁重建 epusdt；不要直接删除数据库卷。 |
| 收银台没有可用地址 | 地址管理中添加并启用对应网络/代币的收款地址。 |

## 十四、安全底线

- `.env`、真实验收证据、缓存和报告均不得上传 GitHub。
- 管理后台不要直接暴露公网；保留独立域名、Basic Auth 和原生 API 鉴权。
- 回调必须同时校验来源 IP 与 HMAC-SHA256。
- 不把私钥/助记词填进任何配置。
- 不启用提现、退款或法币通道。
- 升级 New API/epusdt 前先审查并重放 `patches/` 中的补丁。
